## Top story

**OpenAI is making ChatGPT remember more, and harder to see what it remembers — which turns "memory" into a data-governance question, not a convenience feature.** OpenAI's Dreaming V3, the rewritten memory architecture announced June 4, is now reaching free-tier users for the first time after a roughly 5x cut in the compute cost of running it; US Plus and Pro users got it first, with free and Go users plus more countries rolling out over the coming weeks ([OpenAI](https://openai.com/index/chatgpt-memory-dreaming/), [implicator.ai](https://www.implicator.ai/openai-will-expand-chatgpt-memory-to-free-users-after-5x-compute-cut/)). The capability story is real: OpenAI's own evals report factual recall up from 67.9% to 82.8% and accuracy-over-time from 52.2% to 75.1% as the system now synthesises and updates memories in the background rather than waiting to be told what to save ([OpenAI](https://openai.com/index/chatgpt-memory-dreaming/)).

The wrinkle for schools is in the audit trail. OpenAI concedes the Memory Summary Page "does not necessarily include everything ChatGPT may remember," synthesised memories live in a separate data layer injected at inference time rather than in the visible chat log, deleting a conversation does not delete the memory derived from it, and the "Don't mention this again" control suppresses a memory without removing it ([Tech Times](https://www.techtimes.com/articles/317840/20260605/chatgpt-memory-dreaming-update-openai-rewrites-personalization-engine-limits-audit-trail.htm)). An ACM CHI 2026 study of 2,050 memory entries from 80 users found 96% were created unilaterally by the system, with GDPR-defined personal data in 28% and psychological inferences in 52% — the "personalisation-convenience paradox" that the feature users value most is the one they can least inspect or constrain.

For a Google-Workspace school this is not a stack decision — ChatGPT is rarely core infrastructure in those environments, and managed Gemini and NotebookLM contracts carry their own no-training, school-managed-domain terms. It is a literacy-and-policy fact. Students on personal free accounts now get a persistent profile that builds itself quietly, that they cannot fully see, and that survives a deleted conversation. Any disclosure or data-handling guidance that assumed "delete the chat and it's gone" is now wrong on the consumer tier most students actually use. The EU AI Act's chatbot transparency obligations land August 2; the gap between what these systems retain and what a user can audit is about to be a compliance question, not just a UX one. This strengthens the week's running line: write guidance about how students work and what leaves their account, not about which tool is approved.

## Sceptic's corner

The easy read of the memory upgrade is that better recall is straightforwardly good: ChatGPT now keeps your context current, stops contradicting itself, and the benchmark numbers jumped. All true, and worth having. But notice what the framing quietly does. OpenAI is selling *more* persistence while shipping *less* visibility into it — the Memory Summary Page is explicitly incomplete, the underlying memory layer is not in the chat log you can read, and deleting the conversation no longer deletes what the model inferred from it ([Tech Times](https://www.techtimes.com/articles/317840/20260605/chatgpt-memory-dreaming-update-openai-rewrites-personalization-engine-limits-audit-trail.htm)). A capability gain and a transparency loss arrived in the same release, and only the capability gain came with numbers attached.

The CHI 2026 finding sharpens it: when 96% of memory entries are written by the system unprompted, and half contain psychological inferences, "you're in control of your memories" is doing a lot of load-bearing work for a control surface the vendor admits is partial. That is not an accusation of bad faith — synthesised background memory is genuinely hard to expose cleanly. But it is a reason to resist the convenience-first default. For anyone setting student-use norms, the honest version is not "you can manage what it remembers." It is closer to: assume a personal AI account is accumulating a profile you cannot fully see or fully delete, and decide what you are willing to put into it on that basis. Treat memory transparency as a feature to verify per tool and per tier — not a promise to take at face value.
