# An Agent in the Directory: What It Means to Give AI Its Own Account

_Filed 9 October 2026._

> **Lede:** Google's coworker agent arrives with an email address, a calendar, a Drive and a seat in the company directory. The identity is the least surprising part: Microsoft, Okta and the standards bodies have spent a year converging on the idea that an agent should be a named, governed principal rather than a borrowed human login. What the announcement leaves open is whether the governance arrives as fast as the account does. Google's own documentation says prompt injection is not a solved problem, spending caps are not instantaneous, and deleting an agent leaves its permissions behind. For a school the useful question is not whether an agent can hold an identity. It is whether the school can say who owns it, what it must never read, and how it is switched off ([Google Cloud, 9 October 2026](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)).

## 1. What Google announced, and what it has not yet said

Google's 8 October announcement presents the Gemini agent as a universal agent for work: one prompt box, the organisation's business context, built-in cost controls and enterprise governance ([Google, 8 October 2026](https://blog.google/innovation-and-ai/infrastructure-and-cloud/google-cloud/gemini-at-work/)). Thomas Kurian's keynote account fills in the organisational detail. A user describes a role and Gemini creates a coworker agent, which "receives its own Workspace account, including an email address, calendar, Drive, and presence in your company directory." Colleagues add it to Chat spaces or @mention it; it can reply in Doc comment threads and appears under its own name in version history. Kurian's account is explicit about scope: "A coworker agent acts under its own identity rather than yours, and it sees only what you share with it." Access, Google says, follows existing sharing and membership ([Google Cloud, 9 October 2026](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)).

The same account lists the governance claims: every agent gets an identity "cryptographically attested and governed like an employee," permissions are fine-grained and role-based, every action is written to an audit trail attributed to the agent rather than a person, agents run inside a sandbox, and all traffic passes through an Agent Gateway that enforces policy. The example policy Google gives is "agents may not open documents classified Need to Know." A project-level spending cap pauses the agent when reached ([Google Cloud, 9 October 2026](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)).

What the keynote does not contain is a launch status, an edition list or a price for the coworker agent. VentureBeat's reporting the same day supplies some of that: a Google Cloud spokesperson said the agent is in private preview for a select group of customers, with no general-availability date, and that it will be included at no additional charge wherever Gemini Enterprise is available, including existing Workspace business and enterprise subscriptions. Google had not said whether coworker agents with their own Workspace accounts carry separate licence fees, how many an organisation may create, or whether long-running tasks carry usage charges ([VentureBeat, 8 October 2026](https://venturebeat.com/orchestration/google-cloud-unveils-persistent-gemini-agents-for-long-running-tasks-and-they-get-their-own-gmail-calendar-and-drive-storage)). The reporting does not mention education at all.

Nor does the Workspace documentation settle it. Google's admin help page for turning Gemini Enterprise on or off, updated 7 October, covers the Business, Standard, Plus and Frontline editions, says Gemini Enterprise is not included in a Workspace subscription, and gives admins a single checkbox to let it access Workspace data. It says nothing about agents holding their own accounts, and nothing about Education editions ([Google Workspace Admin Help, updated 7 October 2026](https://knowledge.workspace.google.com/admin/generative-ai/gemini-enterprise/turn-gemini-enterprise-on-or-off-for-users)). **The plain finding: on public evidence, it cannot be established that the coworker agent is available to a Workspace for Education domain, or on what terms.** A school told otherwise should ask for it in writing.

## 2. What the identity layer actually does, per Google's documentation

Google's developer documentation is more concrete than the keynote, though it describes the Cloud agent platform rather than the Workspace coworker account specifically. On Gemini Enterprise Agent Platform, each agent receives a SPIFFE-format identity of the form `spiffe://TRUST_DOMAIN/resources/SERVICE/RESOURCE_PATH`, plus an X.509 certificate that is valid for 24 hours and renewed automatically. Access tokens are cryptographically bound to that certificate so they are harder to replay elsewhere. Administrators grant IAM roles directly to the agent as a principal, and a Principal Access Boundary policy can cap what the agent may reach regardless of other grants. An Auth Manager handles the case where an agent acts on a specific user's behalf via three-legged OAuth, with those access events attributed to the agent's identity ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview)).

Two details in that documentation matter more than the cryptography. First, identity is tied to the hosting resource: redeploy the same agent and it becomes a new principal, so earlier grants no longer apply. Second, and more awkward: "Deleting an agent doesn't remove the IAM bindings that reference its principal." Those bindings remain as inactive grants that someone must remove by hand ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview)). Dismissing an agent, in other words, is a procedure, not a button.

The platform overview page adds that the Workspace Admin console governs how Gemini Enterprise agents interact with Workspace data: admins can enable the service per user, manage access to agents, enforce domain policies on agent data access and review Workspace audit logs of agent interactions. It also describes Agent Gateway as the runtime enforcement point that intercepts an agent's calls to tools and other agents ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/gemini-enterprise-agent-platform/agents)). None of these pages states whether the controls are in Preview or generally available, and none of them describes how a coworker agent's Workspace mailbox and Drive are provisioned, licensed or retired. Those are the gaps a cautious administrator would want closed first.

## 3. Everyone is building the same thing

Google is joining a movement rather than starting one. Microsoft Entra Agent ID, documented since 2025, introduces agent identity "blueprints" that stamp out individual agent identities, and an optional agent user account for agents that need to behave as a team member. Microsoft's documentation describes that account as suited to long-term digital employees with mailboxes, chat access and inclusion in HR systems. It has no password or passkey, authenticates only through its parent agent identity, cannot hold privileged administrator roles, and can be added to ordinary groups, inheriting whatever those groups can reach ([Microsoft Learn, updated 30 September 2026](https://learn.microsoft.com/en-us/entra/agent-id/identity-platform/agent-users)). Extending Entra's security features to agents requires Microsoft Agent 365, which Microsoft lists as an add-on to its education A5 plan among others ([Microsoft Learn, updated 13 August 2026](https://learn.microsoft.com/en-us/entra/agent-id/identity-professional/microsoft-entra-agent-identities-for-ai-agents)).

Microsoft's governance documentation also answers the ownership question more explicitly than Google has so far. Agent identities can be assigned human sponsors accountable for lifecycle and access; access can be granted through packages with expiry dates, which lapse if the sponsor does nothing; and if a sponsor leaves the organisation, sponsorship transfers automatically to their manager ([Microsoft Learn, updated 6 October 2026](https://learn.microsoft.com/en-us/entra/id-governance/agent-id-governance-overview)). Okta made its Agent SSO generally available on 24 August, registering agents as identities in its directory alongside employees and issuing short-lived tokens; its separate Okta for AI Agents product, which Okta says has been available since May, discovers unregistered agents and assigns them named human owners. Okta also cites its own survey finding that only 34% of organisations apply the same security controls to agents as to human workers, a vendor statistic from a company selling the remedy ([Okta, 24 August 2026](https://okta.com/newsroom/press-releases/okta-brings-first-class-identity-to-ai-agents-with-agent-sso/)).

The standards work is younger than the products. The OpenID Foundation's October 2025 whitepaper concluded that existing authentication and authorisation standards can secure many current agent uses, especially within one organisation, but were not designed for recursive delegation chains or cross-domain trust; it recommended treating agents as first-class identities with lifecycle management and accountability ([OpenID Foundation, 7 October 2025](https://openid.net/new-whitepaper-tackles-ai-agent-identity-challenges/)). NIST's National Cybersecurity Center of Excellence published a concept paper in February asking for input on agent identification, authorisation, auditing, non-repudiation and prompt-injection controls; comments closed on 2 April ([NIST, 5 February 2026](https://www.nist.gov/news-events/news/2026/02/new-concept-paper-identity-and-authority-software-agents)). One IETF proposal for on-behalf-of authorisation for AI agents was an individual submission that expired without working-group adoption and, per the datatracker, has no formal standing ([IETF Datatracker, last revision 25 August 2025](https://datatracker.ietf.org/doc/draft-oauth-ai-agents-on-behalf-of-user/)). The direction of travel is clear; the settled rules are not.

## 4. Where it breaks: the documented failure modes

**Permission inheritance and over-sharing.** "It sees only what you share with it" is reassuring only if sharing is tidy. Microsoft's experience with Copilot is instructive: Copilot grounds its answers in data users already have permission to access, and the first pillar of Microsoft's deployment blueprint is remediating oversharing ([Microsoft Learn, updated 18 August 2026](https://learn.microsoft.com/en-us/microsoft-365/copilot/secure-govern-copilot-foundational-deployment-guidance)). An agent added to a Chat space or a group does not need to be granted anything sensitive individually; it inherits what the space or group already holds. The OWASP Top 10 for Agentic Applications lists un-scoped privilege inheritance as the first example of its identity-and-privilege-abuse category ([OWASP GenAI Security Project, 9 December 2025](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)).

**Prompt injection through shared content.** An agent that reads email and shared documents reads whatever an outsider can put there. EchoLeak, disclosed in June 2025, let a single crafted email cause Microsoft 365 Copilot to disclose internal data without any user interaction; Microsoft rated it critical, at 9.3 ([NVD, CVE-2025-32711, published 11 June 2025](https://nvd.nist.gov/vuln/detail/CVE-2025-32711); [Reddy and Gujral, arXiv, 6 September 2025](https://arxiv.org/abs/2509.10540v1)). On Google's side, researchers showed that instructions hidden in emails, calendar invitations and shared documents could hijack Gemini-powered assistants across 14 scenarios, rating 73% of the threats high-critical before Google deployed mitigations that, by the authors' reassessment, reduced the risk to very low to medium ([Nassi, Cohen and Yair, arXiv, 16 August 2025](https://arxiv.org/abs/2508.12175)). Google is candid about the residual risk. Its Workspace security team wrote in April: "IPI is not the kind of technical problem you “solve” and move on." ([Google, 2 April 2026](https://blog.google/security/google-workspaces-continuous-approach-to-mitigating-indirect-prompt-injections/)). A persistent coworker agent that monitors an inbox is a standing target for exactly this.

**Confused deputies.** OWASP's agentic list describes a low-privilege agent relaying valid-looking instructions to a higher-privilege one, which executes them without rechecking the original user's intent; its worked example is a crafted email that an email-sorting agent passes to a finance agent, which then makes a fraudulent payment ([OWASP GenAI Security Project, 9 December 2025](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)). Google's keynote describes Gemini creating temporary sub-agents, each with its own identity, and coordinating them over hours or days ([Google Cloud, 9 October 2026](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)). More identities can mean cleaner attribution. They also mean more trust relationships to get wrong.

**Audit that records actions, not reasons.** Google's attributed audit trail answers "which account did this?" — a real improvement over agents acting through a human's login. It does not, on the evidence published, answer "why?" OWASP's framing is that observability must cover what agents are doing, "why they are doing it, and which tools they are invoking," and its mitigations include binding tokens to a signed intent ([OWASP GenAI Security Project, 9 December 2025](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)). That is guidance, not a shipped feature. A log that faithfully records an agent emailing a parent the wrong document is evidence after the fact, not a control.

**Cost runaway.** Google's spending cap is real but documented with caveats. The Cloud Billing page says: "Due to latency in usage and cost reporting, spend cap enforcement isn't instantaneous." The customer remains responsible for overages accrued in that gap; caps apply to a single project and a single service; subscription costs such as Gemini Enterprise subscriptions are out of scope; and caps are limited to first-party Google Cloud customers, with reseller accounts excluded ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps)). Google's August cost-controls post also describes an option to let usage run on into overage rates rather than pause ([Google Cloud, 27 August 2026](https://cloud.google.com/blog/products/ai-machine-learning/flexible-billing-and-cost-controls-for-agents-on-google-cloud)). A school that buys through a reseller should treat the keynote's "hard limit" as a question, not an assumption.

**Offboarding.** Human accounts have a leaver process because HR forces one. Agents have no HR record. Google's documentation already shows that deletion leaves inactive grants behind ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview)); Microsoft's answer is a sponsor whose departure hands the agent to their manager ([Microsoft Learn, updated 6 October 2026](https://learn.microsoft.com/en-us/entra/id-governance/agent-id-governance-overview)). Google has not yet published an equivalent for a coworker agent's mailbox, Drive contents or Chat memberships. An inference, flagged as such: the first real incident in a school will not be a dramatic hijack but an agent created by someone who has since left, still sitting in a shared drive.

## 5. What it means for a school

A school's Workspace is not a corporate tenant with a few sensitive folders; it is an organisation where shared drives, Chat spaces and Google Groups routinely contain student names, grades, learning-support notes, safeguarding records and attendance. "It sees only what you share with it" therefore means an agent added to a department space or a grade-level group sees what that space holds, including whatever was shared into it carelessly years ago. National data-protection law applies as well. Vietnam's PDPL, for example, in force since 1 January 2026, requires parental consent for processing children's data and carries over impact-assessment duties that must be updated as processing changes ([Tilleke & Gibbins, 27 August 2025](https://tilleke.com/insights/vietnams-new-personal-data-protection-law-a-closer-look)). Under laws of that kind, a new processing actor reading student records is plausibly such a change; that is a question for a school's data-protection officer, not a technicality.

Three further points follow. First, availability: nothing published establishes that the coworker agent will reach a Workspace for Education domain, so there is no decision to make yet, only questions to have ready. Second, the learning platform: where grades live in a system outside Google, an agent's reach into Google matters less for assessment records, but staff planning, communications and student-support material typically still live in Drive and Chat. Third, ownership: individual, named access rather than group-based grants is precisely the discipline an agent account would need, and it is worth establishing before anyone proposes adding an agent to an all-staff group.

A sensible pilot, if and when it is available, would look like a convincing demonstration rather than a launch: one small permitted task (say, drafting a weekly digest from a single non-student shared drive); one prohibited resource that stays inaccessible when the agent is asked, tricked or injected into reaching it; an action history a non-specialist can read; and a clean stop, both by spending cap and by deletion, followed by a check that no grants or memberships remain.

## 6. The sceptic's case

The strongest argument against this is not that agents fail. It is that the identity frame quietly changes what is being bought. Treating an agent "like an employee" borrows the governance vocabulary of employment, but employees come with judgement, liability, a contract and a manager, and an agent has none of these; the directory entry gives it the access of a colleague without the accountability of one. Microsoft's own document recommends the agent user account only where an agent genuinely needs to act as a user ([Microsoft Learn, updated 30 September 2026](https://learn.microsoft.com/en-us/entra/agent-id/identity-platform/agent-users)), and OWASP's core advice is what it calls Least-Agency: avoid autonomy that is not needed, because unnecessary autonomy expands the attack surface without adding value ([OWASP GenAI Security Project, 9 December 2025](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)). The sales pitch runs the other way: give the agent a mailbox and a persistent role and find work for it.

Second, it is premature on Google's own evidence. The product is in private preview, unpriced, and without published licensing for the accounts it creates ([VentureBeat, 8 October 2026](https://venturebeat.com/orchestration/google-cloud-unveils-persistent-gemini-agents-for-long-running-tasks-and-they-get-their-own-gmail-calendar-and-drive-storage)); its injection defences are described by Google as continuous rather than complete ([Google, 2 April 2026](https://blog.google/security/google-workspaces-continuous-approach-to-mitigating-indirect-prompt-injections/)); and the standards for delegation are still at the concept-paper stage ([NIST, 5 February 2026](https://www.nist.gov/news-events/news/2026/02/new-concept-paper-identity-and-authority-software-agents)). Third, schools are the wrong first customer. Their data is disproportionately about children, their sharing habits are the accumulated work of hundreds of non-specialists, and their IT teams are small. The organisations best placed to absorb the governance cost are the large banks and enterprises showcased in Google's keynote, not a school whose administrator is also fixing projectors. The fair rebuttal is that an agent with its own identity is safer than an agent borrowing a teacher's login, which is what many ad hoc automations do today. That is true, and it is an argument for identity, not for persistence or autonomy.

## 7. What a school should actually do

**Do nothing irreversible now; there is nothing yet to switch on.** Note the private-preview status and check Google's Workspace for Education updates for any agent-account feature before any discussion of rollout.

**Fix the sharing before an agent can inherit it.** Audit the shared drives, Chat spaces and groups most likely to receive an agent first. Anything containing student data that is shared more widely than its purpose needs is a problem today; an agent makes it a faster one ([Microsoft Learn, updated 18 August 2026](https://learn.microsoft.com/en-us/microsoft-365/copilot/secure-govern-copilot-foundational-deployment-guidance)).

**Write the agent policy as a staff policy would be written.** Every agent has a named human owner; ownership transfers on departure; access is granted individually and expires by default; agents are never added to groups that contain student records; prohibited resources are named; dismissal includes removing grants and memberships, since Google's documentation says deletion does not ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview)).

**Ask the vendor five questions in writing.** Is the coworker agent available to the school's edition, and does each agent consume a licence? Can an administrator block agents from specified organisational units, drives and labels, and is that enforced at the gateway or only by sharing? What does the audit log record beyond the action, and can a non-specialist read it? Does the spend cap apply to the school's purchasing route, and how much can be spent before it bites ([Google Cloud documentation, updated 7 October 2026](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps))? What happens to an agent's mailbox and Drive when it is deleted?

**When a pilot is possible, make it a test, not a launch.** One permitted task with no student data; one prohibited resource, attacked deliberately with a planted instruction in a shared document; one readable action history; one clean stop. If any of the four fails, the finding is the result. Count the human checking time honestly. An agent whose errors can only be caught by a person reading everything it does has not saved that person's time; it has moved it.
